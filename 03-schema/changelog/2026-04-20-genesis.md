# LinkcOS 初始搭建

## 1. 迭代原因

### 触发信号
陈言希望建立一套基于 Claude Code 的个人操作系统，
用于日常事务管理、知识积累、目标追踪和自我反思。

### 根本问题
传统笔记和任务工具需要大量手动维护——归档、关联、复盘。
LLM 可以承担这些"簿记"工作，让人专注于思考和决策。

## 2. 具体迭代内容

### 新增
- 三层架构：`01-raw/`（不可变原始层）、`02-wiki/`（LLM 编译层）、`03-schema/`（元配置层）
- 三定律人格宪法：平等协作、成长迭代、诚实反馈
- 9 种初始 wiki 页面类型（person, org, product, project, short-goal, long-goal, concept, decision, review）
- 每种类型的 Obsidian 模板
- Wiki 编译纪律（基于 Karpathy LLM-Wiki 模式）
- Obsidian CLI 集成约定
- 双周提案制（Schema 演化机制）
- Update Log 纪律（changelog 四字段必填制）
- `02-wiki/index.md` 含 Dataview 动态视图
- `02-wiki/log.md` append-only 时间线

### 设计参考
- Karpathy LLM-Wiki gist（2026-04-04）
- Anthropic Claude Code 官方文档（memory、skills、hooks、subagents）
- 社区最佳实践（HumanLayer、Builder.io、DEV Community）
- ETH Zurich 关于 LLM schema 漂移的研究

## 3. 有什么改进

### 直接改进
- 从零到一：陈言有了一个结构化的个人操作系统
- 输入即编译：语音/文字/截图进来时自动分类关联
- 系统可成长：双周提案 + Update Log 让架构持续演化

### 系统级改进
- 建立了"人类输入 → LLM 编译 → 知识复利"的基本循环
- 建立了"日常信号 → 双周提案 → 审批执行 → changelog 记录"的演化管线

## 4. 可能的影响

### 已评估的风险
- ⚠️ 初始类型集可能不完整——预期在前 30 天通过训练期迭代
- ⚠️ 模板字段可能过多或过少——依赖实际使用反馈调整

### 待观察的影响
- 📊 陈言的实际输入频率和类型分布
- 📊 Claude Code 的编译准确率（前 30 天重点监控）
- 📊 双周提案的质量是否足以驱动有效演化

### 回退预案
这是 genesis，无需回退。若整套架构不适合，可重新设计。
